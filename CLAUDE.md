# Dropdown Panel Web Component

## Project Overview

This is a lightweight, accessible dropdown/popover web component library built with vanilla JavaScript and the Web Components API. It provides compact popover-style dropdowns, full-width mega menus, and nested submenus.

**Philosophy: Minimal Styling**

The core stylesheet contains only the CSS required for functionality. This makes it:

- Easy to integrate into any project
- No opinionated styles to override
- Lightweight - 1,019 bytes minified, 464 bytes gzipped
- Works with Tailwind, Bootstrap, CSS-in-JS, or plain CSS

Users add their own styling (colors, shadows, spacing, typography). Entrance animation is available but opt-in, in a second stylesheet.

Shipping size, min + gzip: 2,798 bytes JS, 464 bytes core CSS, 412 bytes effects CSS.

## Architecture

### Component Structure

The library consists of three custom elements that work together:

1. **`<dropdown-component>`** - Main container that owns all state and behavior
2. **`<dropdown-trigger>`** - Button element that toggles the dropdown
3. **`<dropdown-panel>`** - Content container: popover, wide, or right-opening

All logic lives in `dropdown-component`. The other two only assign themselves an id and their baseline attributes.

## Usage Examples

### Basic Popover Dropdown (Default)

```html
<dropdown-component>
	<dropdown-trigger>Menu</dropdown-trigger>
	<dropdown-panel>
		<a href="#" class="dropdown-item">Profile</a>
		<a href="#" class="dropdown-item">Settings</a>
		<div class="dropdown-divider"></div>
		<a href="#" class="dropdown-item">Logout</a>
	</dropdown-panel>
</dropdown-component>
```

**Behavior:**

- Host is `position: relative`; the panel is absolutely positioned at `top: 100%; left: 0`
- Opens on hover (fine pointers) and on click, unless `trigger` says otherwise
- Fades in over 200ms; anything more is opt-in via `effect`
- No width, background, radius or padding - all of that is the consumer's

### Full-Width Mega Menu

```html
<nav class="menubar">
	<!-- .menubar { position: relative } -->
	<dropdown-component>
		<dropdown-trigger>Products</dropdown-trigger>
		<dropdown-panel wide>
			<div class="column">
				<h3>Software</h3>
				<a href="#" class="dropdown-item">Web Apps</a>
			</div>
			<div class="column">
				<h3>Hardware</h3>
				<a href="#" class="dropdown-item">Laptops</a>
			</div>
		</dropdown-panel>
	</dropdown-component>
</nav>
```

**Behavior:**

- Panel is `width: 100%`; the host goes `position: static`
- The panel therefore positions against the nearest **positioned ancestor**, not the host - that ancestor is the consumer's job. With none, `top: 100%` resolves against the initial containing block and the panel lands a viewport-height below the fold
- Layout (grid, columns, padding) belongs to the consumer

### Nested Dropdowns

A dropdown inside a panel is just another dropdown. Use `opens="right"` for submenus:

```html
<dropdown-component>
	<dropdown-trigger>Resources</dropdown-trigger>
	<dropdown-panel>
		<a href="#">Documentation</a>

		<!-- Nested dropdown opens to the right -->
		<dropdown-component>
			<dropdown-trigger class="dropdown-item">Support</dropdown-trigger>
			<dropdown-panel opens="right">
				<a href="#">Contact Us</a>
				<a href="#">Help Center</a>
			</dropdown-panel>
		</dropdown-component>

		<a href="#">Blog</a>
	</dropdown-panel>
</dropdown-component>
```

**Important:**

- CSS selectors use `>` child combinators so they only affect direct children, never nested components
- `dropdown-component` is `display: inline-block`; a nested one needs `dropdown-panel dropdown-component { display: block }` or it renders as a narrow inline row
- Nothing in the chain may set `overflow: hidden` - it clips the submenu at the parent panel's edge

## Key Design Decisions

### 1. `visible` on the Host is the Single Source of Truth

**Decision:** One reflected boolean attribute, `visible`, on `<dropdown-component>` holds open state. `aria-expanded`, `aria-hidden` and `inert` are derived outputs, written by `#applyState()` and never read back.

**Rationale:**

- Consumers get one thing to set, observe and style off - `dropdown-component[visible]`
- ARIA stays correct by construction instead of by convention
- Setting the attribute from outside works: `attributeChangedCallback` routes it to `show()`/`hide()`, with a `#reflecting` guard so internal writes do not re-enter

**Implementation:** `#visible` (private) is the internal state; `#reflect()` writes the attribute; `#applyState()` pushes the derived attributes onto trigger and panel.

### 2. Single Panel Component with `wide` Attribute

**Decision:** One `<dropdown-panel>` with an optional `wide` attribute, not two separate components.

**Rationale:**

- Simpler API - one component instead of two
- They are the same thing with different CSS
- The attribute describes the layout variant, which is more semantic

**Implementation:**

```css
/* position logic handled purely in CSS, in src/dropdown-panel.css */
dropdown-component:has(> dropdown-panel:not([wide])) {
	position: relative;
}

dropdown-component:has(> dropdown-panel[wide]) {
	position: static;
}
```

This is why `:has()` is the real browser floor: without it the host never becomes `position: relative` and every popover mispositions.

### 3. No ARIA Menu Roles

**Decision:** Do NOT use `role="menu"`, `role="menubar"`, or `role="menuitem"`.

**Rationale:**
Following [Adrian Roselli's accessibility guidance](https://adrianroselli.com/2017/10/dont-use-aria-menu-roles-for-site-nav.html):

- These roles are for application menus (File/Edit in desktop apps), not website navigation
- They create expectations for complex keyboard interactions that are rarely implemented
- Screen readers announce them as application menus, which confuses users

**What we DO use:**

- `role="button"` and `tabindex="0"` on `<dropdown-trigger>` (set only if absent)
- `aria-haspopup="true"`, `aria-expanded` and `aria-controls` on the trigger
- `role="group"` on the panel, **only when it has no role of its own** - a role-less custom element cannot carry an accessible name, so `aria-labelledby` would be inert without it
- `aria-hidden` and `inert` on the panel

### 4. Direct Child Selectors in CSS

**Decision:** Use `>` child combinators in hover and state selectors.

**Rationale:** Prevents styles from reaching nested dropdowns inside panel content.

```css
/* ✓ Correct - only affects direct children */
dropdown-component:hover > dropdown-trigger::before

/* ✗ Wrong - would affect nested triggers too */
dropdown-component:hover dropdown-trigger::before
```

### 5. Direction Control with `opens` Attribute

**Decision:** `opens="right"` controls the opening direction.

**Rationale:**

- Enables nested menus that open sideways
- Value-based, so it stays extensible ("left", "up" later)
- Default (down) needs no attribute
- Each direction gets its own hover bridge geometry

**Implementation:**

```css
dropdown-panel[opens='right'] {
	top: 0;
	left: 100%;
}

/* inside @media (hover: hover) */
dropdown-component:has(> dropdown-panel[opens='right']):hover
	> dropdown-trigger::before {
	left: calc(100% - 30px);
	top: -10px;
	width: 40px;
	height: calc(100% + 20px);
	transform-origin: center left;
	transform: perspective(50px) rotateY(-50deg);
}
```

### 6. No `visibility` in the Core CSS

**Decision:** Hidden state is `opacity: 0` + `pointer-events: none` + `inert` + `aria-hidden`. `visibility` appears nowhere, and the transition is declared as longhands.

**Rationale:** `visibility` has to be transitioned to survive a fade-out. Any consumer writing `transition: opacity 300ms` resets the whole shorthand, silently kills that transition, and the panel snaps away mid-fade. That bug shipped in v1.0.0. Hit-testing is `pointer-events`, assistive tech is `aria-hidden`, tab order and find-in-page are `inert` - none of which a consumer's shorthand can break.

### 7. Effects Live in a Second Stylesheet

**Decision:** `effect="fade|slide|scale|blur|swing"` and the whole trigger-arrow feature are no-ops unless `@magic-spells/dropdown-panel/css/effects` is loaded.

**Rationale:** Nobody pays for animation they did not ask for, and the core stays under a kilobyte. Effects are tunable with `--dp-effect-duration` and `--dp-effect-easing`, adapt to `wide` and `opens="right"`, and all collapse to a plain opacity fade under `prefers-reduced-motion: reduce`.

**Gotcha:** the core 200ms fade is a hard-coded duration. `--dp-effect-duration` only reaches panels that carry an `effect`.

### 9. The Trigger Arrow is a Data-Attribute Hook

**Decision:** `data-dropdown-arrow` on a real child of the trigger. Behaviour comes from `arrow="flip|static|none"` on the host, shape from `arrow-shape="chevron|triangle"`, both in the effects stylesheet.

**Rationale:** A published hook belongs in a namespace the package owns. A class name (`.dropdown-arrow`) collides with utility frameworks and gets hashed away by CSS-modules and scoped-style pipelines; `data-*` survives both and reads as a behaviour hook rather than a style hook, leaving the consumer's own class free for size and colour. Host placement matches `visible` and `trigger`, and each nested `<dropdown-component>` carries its own, so a submenu can differ from its parent.

**Empty hook vs your own glyph:** `[data-dropdown-arrow]:empty` is what the sheet draws into. Non-empty and it only applies the open/close behaviour. `:empty` is literal - whitespace is content, so the tag has to close tight.

**No rotation, ever.** The chevron is two bars pivoting about one point, each swinging through the horizontal, so the pair passes through a flat dash at the midpoint and lands mirrored - inherently symmetric, and close retraces open. The triangle cannot flap, so it mirrors: `scaleY(-1)`, or `scaleX(-1)` on `opens="right"`, where the drawn glyph also points the way it opens (`--_dp-arrow-dir: -90deg`). A `rotate(180deg)` reads as directional and unwinds on close.

**Specificity note:** the direction rules wrap their `:has()` in `:where()` so they do not out-specify the `arrow="static"` / `arrow="none"` opt-outs, which tie with the state rules and win on source order. Keep those opt-out rules last.

**Reduced motion:** the arrow still flips - it is a state readout, not decoration - it just lands instantly (`transition-property: none`).

### 8. Interaction Mode is Per-Dropdown

**Decision:** `trigger="hover|click|both"` on the host, default `both`.

**Rationale:** A nav bar and a settings popover want different things. `hover` falls back to click where `(hover: hover)` does not match (`#clickEnabled()`), so a hover-only menu is never unopenable on a phone.

**Hover intent:** `open-delay` and `close-delay` (milliseconds, both default `0`, both observed alongside `visible`) delay only the hover path. One `#hoverTimer` field holds at most one pending open or close; `#afterDelay()` runs the action synchronously when the delay is `0`, so the default is byte-for-byte the old behaviour. `pointerenter` cancels a pending close (the forgiving companion to the hover bridge) and `pointerleave` cancels a pending open. `#open()` and `hide()` clear the timer, so click, keyboard and API paths never wait; a latched panel ignores `close-delay` because it does not close on leave at all. `disconnectedCallback` clears it too. Non-numeric and negative values resolve to `0`.

## Component Communication

### How Components Work Together

1. **On mount** (`dropdown-component.connectedCallback` → `#setup()`):

   - Finds direct child `<dropdown-trigger>` and `<dropdown-panel>` (`:scope >`)
   - Mints ids from the shared counter in `uid.js`, wires the ARIA relationships
   - Applies the closed state directly (not via `hide()`, whose idempotency guard would skip it)
   - Attaches listeners, then honors a `visible` attribute that was already present
   - If the children are not there yet, `#waitForChildren()` starts a `MutationObserver` and re-runs setup when they arrive. The console warning only fires after a deferred check (`DOMContentLoaded`, or a frame plus a task), so a non-deferred script tag or framework hydration is recoverable rather than fatal.

2. **Pointer enters the host** (fine pointers only):

   - `pointerenter` → `#open('hover')`, skipping `pointerType === 'touch'`, `trigger="click"`, and a click-dismissed suppression flag

3. **Click on the trigger:**

   - Ignored when the target is a real control nested inside the trigger (`#isInteractiveDescendant`)
   - Closed → `#open('click')`
   - Open **from hover** → promoted to click-open and latched. Closing here would strand it shut, because `pointerenter` cannot fire again while the pointer is still inside.
   - Open from anything else → `hide()`, and hover is suppressed until the pointer leaves

4. **Pointer leaves the host:**

   - `pointerleave` clears hover suppression, then closes **only** if `#openSource === 'hover'`. Click-, keyboard- and API-opened panels latch.

5. **Pointerdown outside an open panel:**

   - Document listener registered on open, removed on close. Calls `hide()` when the target is outside the component.

6. **Any dropdown opening:**

   - `#closeOthers()` closes every other open dropdown that is not an ancestor or descendant of the one opening

7. **Keyboard** (trigger-level handler plus a document handler registered on open):
   - Enter/Space on the trigger toggles
   - ArrowDown/ArrowUp on a closed trigger open it and focus the first/last item
   - ArrowRight on a closed trigger whose panel is `opens="right"` opens it
   - ArrowDown/ArrowUp/Home/End rove the panel's own focusable descendants, wrapping
   - ArrowLeft closes an `opens="right"` panel and returns focus to its trigger
   - Escape closes this level only and focuses its trigger - it works for hover-opened panels too, because the keydown listener is on `document`, not on the panel
   - Progressive disclosure comes from `if (_.querySelector('dropdown-component[visible]')) return;` - only the innermost open dropdown answers a key. (v1.0.0 used `stopPropagation()` for this; it does not any more.)
   - Arrow keys are skipped inside `input`, `textarea`, `select` and `contenteditable`
   - Focus leaving a panel does NOT close it (intentional - users must be able to tab into the panel)

### Event Flow

```
User action (hover / click / tap / key / API)
                    ↓
      #open(source) or hide({ restoreFocus })
                    ↓
      Guards: #setup() resolved? already in target state?
                    ↓
      dropdown-panel:before-show / before-hide   ← cancelable, preventDefault() aborts
                    ↓
      #closeOthers()  (on open)  /  close nested panels, restore focus  (on close)
                    ↓
      #reflect()  →  writes the `visible` attribute on the host
                    ↓
      #applyState()  →  aria-expanded, aria-hidden, inert  (derived output)
                    ↓
      document pointerdown + keydown listeners attached / removed
                    ↓
      CSS responds to [aria-hidden] and [visible]; panel fades in or out
                    ↓
      dropdown-panel:show / dropdown-panel:hide
```

All four events bubble and carry `detail: { trigger, panel }`.

## Styling System

### Minimal Functional Styles

`src/dropdown-panel.css` in full, minus its comments:

```css
dropdown-component {
	display: inline-block;
}

dropdown-component:has(> dropdown-panel:not([wide])) {
	position: relative;
}

dropdown-component:has(> dropdown-panel[wide]) {
	position: static;
}

dropdown-trigger {
	position: relative;
	cursor: pointer;
	user-select: none;
}

/* Hover bridge - rendered only while hovered, and only where a
   pointer can hover, so iOS sticky hover cannot strand an invisible
   strip over the neighbouring nav item after a tap. */
@media (hover: hover) {
	dropdown-component:hover > dropdown-trigger::before {
		content: '';
		position: absolute;
		left: -20px;
		top: 50%;
		width: calc(100% + 40px);
		height: 30px;
		transform-origin: top center;
		transform: perspective(50px) rotateX(50deg);
		z-index: 10;
	}

	dropdown-component:has(> dropdown-panel[opens='right']):hover
		> dropdown-trigger::before {
		left: calc(100% - 30px);
		top: -10px;
		width: 40px;
		height: calc(100% + 20px);
		transform-origin: center left;
		transform: perspective(50px) rotateY(-50deg);
	}
}

/* z-index 11 sits above the bridge at 10, so an unstyled panel does
   not have the top strip of its first item eaten. */
dropdown-panel {
	position: absolute;
	top: 100%;
	left: 0;
	z-index: 11;
	opacity: 0;
	pointer-events: none;
	transition-property: opacity;
	transition-duration: 200ms;
	transition-timing-function: ease-out;
}

dropdown-panel[opens='right'] {
	top: 0;
	left: 100%;
}

dropdown-panel[wide] {
	width: 100%;
}

dropdown-panel[aria-hidden='false'] {
	opacity: 1;
	pointer-events: auto;
}
```

Notes:

- The bridge is symmetric (`left: -20px` / `width: calc(100% + 40px)`). The `[aria-expanded='true']::before` variant from v1.0.0 is gone - it left a hit-testable strip over the next nav item once the pointer had moved on.
- Transitions are longhands so a consumer overriding one property does not have to restate the rest.

## Common Styling Patterns

### Basic Panel Styling

```css
dropdown-panel {
	background: white;
	box-shadow: 0 2px 8px rgba(0, 0, 0, 0.15);
	border-radius: 8px;
	padding: 0.5rem 0;
	min-width: 200px;
```

### Right-Aligned Popover

```css
dropdown-panel {
	left: auto;
	right: 0;
}
```

### Animated Entrance

Prefer the `effect` attribute plus the effects stylesheet. Hand-rolled, it looks like this - note the longhands and the state selector:

```css
dropdown-panel {
	transform: translateY(10px) scale(0.95);
	transition-property: opacity, transform;
	transition-duration: 200ms;
	transition-timing-function: ease-out;
}

dropdown-panel[aria-hidden='false'] {
	transform: none;
}
```

### Styling Off the Open State

```css
dropdown-component[visible] > dropdown-trigger {
	color: #d8b043;
}

```

The arrow flip is not yours to write - the effects stylesheet does it. See below.


### Dropdown Indicators

The hook is `data-dropdown-arrow` on a **real child** of the trigger. Never a `::before` or `::after` on `dropdown-trigger` itself - that box is the hover bridge, and your rule cascades onto it. Pseudo-elements on the hook element are a different box and are fine; they are what the effects stylesheet uses.

```html
<!-- empty hook: the effects stylesheet draws and animates the glyph -->
<dropdown-trigger>
	Products<span data-dropdown-arrow aria-hidden="true"></span>
</dropdown-trigger>

<!-- your own glyph: the sheet draws nothing, only flips it -->
<dropdown-trigger class="dropdown-item">
	Support<span data-dropdown-arrow aria-hidden="true">
		<svg viewBox="0 0 12 12" fill="currentColor"><path d="M6 8L2 4h8z" /></svg>
	</span>
</dropdown-trigger>
```

Settings, both on the host, both effects-stylesheet only:

| Attribute     | Values                       | Default   |
| ------------- | ---------------------------- | --------- |
| `arrow`       | `flip`, `static`, `none`     | `flip`    |
| `arrow-shape` | `chevron`, `triangle`        | `chevron` |

`arrow="none"` hides the hook with `display: none`, so arrows can be turned off without touching the markup; in a flex trigger the `gap` goes with it. The glyph is decorative - keep `aria-hidden="true"` on the hook, since hiding it visually is not the same as keeping it out of the accessibility tree.

Size the drawn glyph with `--dp-arrow-size` (default `0.64em`) and `--dp-arrow-thickness` (default `1.5px`). It is timed by `--dp-effect-duration` / `--dp-effect-easing` like everything else in that sheet.

A custom SVG must be drawn symmetric about the centre of its viewBox on the mirror axis, or `scaleY(-1)` visibly shifts it instead of mirroring it.

## Debugging Tips

### Panel not showing?

1. Check the console for "dropdown-component requires `<dropdown-trigger>` and `<dropdown-panel>` as direct children" - it only fires after a deferred re-check, so if you see it, the children really are missing or not direct
2. Check whether the host has `visible` when it should (inspect the element)
3. Check whether something is canceling `dropdown-panel:before-show`

### Panel showing in the wrong place?

1. `:has()` support - without it the host never gets `position: relative`
2. For `wide` panels, check that an ancestor is positioned. With none, the panel resolves `top: 100%` against the initial containing block.

### Fade-out snapping instead of animating?

Look for a `transition:` shorthand in the consumer's CSS. It resets every longhand the package declared.

### Nested dropdowns interfering?

1. Make sure your CSS uses `>` child combinators
2. Check for `overflow: hidden` anywhere in the chain
3. Nested components need `display: block` to fill the row

### Hover bridge not working?

1. **Never declare `::before` on `dropdown-trigger`** - that is the bridge, and your rule cascades onto the same box
2. Use a real `<span data-dropdown-arrow>` for indicators. Pseudo-elements *on that span* are fine - the rule is about the trigger, not about pseudo-elements generally
3. The bridge only renders under `@media (hover: hover)` and only while `:hover` matches - it is correctly absent otherwise

### Styles not applying?

1. Ensure the CSS is imported: `@magic-spells/dropdown-panel/css`
2. Effects also need `@magic-spells/dropdown-panel/css/effects`, or `effect` is a no-op
3. The component is unstyled by default - you must add your own

An agent's work ends at a commit. **Do not tag, and do not publish** - Cory does both himself.

1. Update the version in `package.json`
2. Run `npm run build` to regenerate `dist/` and `demo/dist/`
3. Run `npm run lint`
4. Test the demo locally with `npm run dev`
5. Update `README.md`, `CLAUDE.md` and `dropdown-panel.d.ts` with any API changes
6. Commit

Tagging (`git tag vX.Y.Z`) and `npm publish` are the repo owner's, not an agent's. Work happens on `feat/*` branches merged into a `release/x.y.z` branch; `main` is not the working trunk.

## Notes for Future Development

- Ids come from one shared module-level counter in `src/uid.js`. Two independent counters previously minted the same `dropdown-trigger-N` and pointed `aria-labelledby` at the wrong element. `ensureId()` also re-mints an id that a different element already claims, which is what stops a `cloneNode(true)` copy from inheriting the original's wiring.
- `inert` genuinely hides closed panels now, and `hide()` restores focus **before** applying it: `inert` synchronously blurs a focused descendant to `<body>`, which would lose the user's place in the tab order. `#applyState()` also sets `inert` before `aria-hidden` when closing, because Chrome warns if `aria-hidden` lands on a focused subtree first.
- The real browser floor is `:has()` (Chrome 105, Safari 15.4, Firefox 121) and `inert` (Chrome 102, Safari 15.5, Firefox 112) - effectively Chrome/Edge 105+, Safari 15.5+, Firefox 121+. Nothing is polyfilled.
- `.trigger` (the element) and the `trigger` attribute (the mode) collide by name. The property is kept from v1.0.0 for back-compat; the mode is read through `.triggerMode`. Renaming either is a breaking change.
- `dropdown-panel.d.ts` is hand-written and not generated - update it alongside any API change.
- Focus is not trapped inside an open panel. That is deliberate for site navigation, but a modal-style variant would want it.
- `opens="right"` assumes LTR.
